# Migrating from go-wallet-toolbox

`go-arcade-toolbox` keeps go-wallet-toolbox's public API, so for the shared
surface **the migration is a module-prefix swap on your import paths**. The
behavior deltas below are where you need to pay attention.

## Import-path rewrite

Change the module prefix on every import:

```
github.com/bsv-blockchain/go-wallet-toolbox  →  github.com/galt-tr/go-arcade-toolbox
```

e.g. `s#go-wallet-toolbox#go-arcade-toolbox#` across your imports. These
sub-paths line up 1:1 (same package name, same location):

| Package | Old | New |
|---|:--:|:--:|
| `pkg/wallet` (+ `pkg/wallet/pending`) | ✓ | ✓ |
| `pkg/wdk` (+ `pkg/wdk/primitives`) | ✓ | ✓ |
| `pkg/defs` | ✓ | ✓ |
| `pkg/services` | ✓ | ✓ |
| `pkg/storage` | ✓ | ✓ |
| `pkg/brc29` | ✓ | ✓ |
| `pkg/certificates` | ✓ | ✓ |
| `pkg/monitor` | ✓ | ✓ |
| `pkg/randomizer`, `pkg/logging`, `pkg/tracing`, `pkg/errors` | ✓ | ✓ |

**Packages that no longer exist** (drop these imports — see the dropped-feature
list): `pkg/certifier`, `pkg/entity`, `pkg/infra`, `pkg/server`.

**New packages** (arcade-only internals, nothing to rewrite from):
`pkg/arcade`, `pkg/headers`, `pkg/utxostore`.

## The API is byte-compatible

Compatibility is enforced by a compat harness (`compat/compat_test.go`) that is a
compile-time and behavioral replica of real go-wallet-toolbox call sites — "a
go-wallet-toolbox user switches over by changing import paths only." It proves
this two ways:

- **Compile-time interface assertions.** If a signature, field, tag, or generic
  constraint drifts, the file stops compiling. The load-bearing one is
  `var _ wdk.WalletStorageProvider = (*stubWalletStorageProvider)(nil)` — the
  21-method storage interface — alongside `var _ sdk.Interface = (*wallet.Wallet)(nil)`
  (the full BRC-100 wallet interface), `var _ wdk.Services = (*services.Services)(nil)`,
  and the storage `Provider`/`Client`.
- **JSON wire-format pinning.** Golden strings generated by marshaling identical
  literals against go-wallet-toolbox itself are asserted with `assert.JSONEq` —
  any tag or type change that alters the wire format, in either direction, fails
  the test (`ValidCreateActionArgs` and `ListOutputsResult` are pinned).

On top of that the wallet passes the BRC-100 conformance vectors ported from the
`ts-stack` reference: **377 vectors executed end-to-end** — `getNetwork` (5),
`getPublicKey` (201), `listActions` (16), `listOutputs` (144),
`internalizeAction` (2), `proveCertificate` (1), and `relinquishOutput` (8) — of
490 embedded; the remainder await real BEEF/cert fixtures upstream
(`pkg/wallet/brc100_conformance_test.go`).

## Behavior deltas

These compile identically but *behave* differently — read them:

- **`wdk.Services` interface is identical; the implementation shrank.** The
  interface is byte-for-byte the same ten methods. But `pkg/services` is now a
  thin adapter that delegates every method to `arcade.TxOracle` + `headers.Headers`.
  Gone: the multi-provider fallback queues and the broadcast router's failover
  chain — Arcade is the single broadcast target, with the circuit-breaker +
  backpressure behavior around it. If you constructed a `wdk.Services` yourself,
  it still plugs in via `wallet.WithServices`.
- **JSON-RPC is dropped; remote storage is REST.** The old JSON-RPC transport is
  gone. Remote/multi-user storage is now the REST `/storage/v1` server + client
  (`storage.NewServer` / `storage.NewClient`, `cmd/storage-server`), which is a
  drop-in `wdk.WalletStorageProvider`. See [storage](storage.md).
- **`reject → release` is now automatic and verified.** The old manual `unfail`
  is replaced by the reject→release reconciler: async-rejected transactions have
  their inputs auto-released **after two-pass verification**, with a double-spend
  winner-union rule. No manual unfail, no UTXO leak. See
  [reject-release-vs-unfail](reject-release-vs-unfail.md) for the full comparison
  and [arcade-integration](arcade-integration.md#the-rejectrelease-reconciler)
  for the guard rules.
- **ChainTracks config key `remote_url` → `url`.** The type is renamed
  `ChaintracksClient` → `ChainTracks`, the embedded/remote `mode` toggle and its
  `storage_path`/`bootstrap_*`/`p2p_*` keys are removed, and the single URL key is
  now `url`. In the arcade-only posture ChainTracks always runs remotely inside
  the Arcade deployment (`:8083/chaintracks/v2`); leave `url` empty to derive it
  from the Arcade URL.
- **Arcade defaults / networks.** The default mainnet Arcade is
  `https://arcade-v2-us-1.bsvblockchain.tech`; the public Teranode Test Net (`ttn`)
  default is `https://arcade-v2-ttn-us-1.bsvblockchain.tech`. The private `tstn`
  network is env-driven (`TSTN_ARCADE_URL`, `TSTN_CHAINTRACKS_URL`). Networks are
  `main | test | ttn | tstn`; `test` disables both external services (offline).
  `GorillaPoolArcURL` is gone.
- **`defs.Version` is unchanged.** It is still the string
  `"go-wallet-brc100-0.0.1"` (only the doc comment changed). Anything that emits
  it on the wire (User-Agent, storage settings) stays byte-identical across the
  migration — the string still literally says `go-wallet-brc100`.

## Dropped features

| Dropped | Replacement / note |
|---|---|
| WhatsOnChain / Bitails / GorillaPool ARC / TAAL integrations | Arcade is the single tx-truth oracle. No multi-provider fallback, no broadcast failover chain (only the arcade circuit breaker + backpressure). |
| `BsvExchangeRate` (exchange-rate feed) | Fees are a static `sat/kb` config (`defs.FeeModel`, default 100 sat/KB). |
| `GetScriptHashHistory` | No indexer in the arcade-only posture. |
| `GetUtxoStatus` / `IsUtxo` / UTXO discovery | The local ledger is the only record of a wallet's coins. See the hard limitation below. |
| GORM | Raw `database/sql` over `pgx` + pure-Go `modernc.org/sqlite`, `goose` migrations. |
| MySQL | Retained only as an enum for config compile-compat; `defs.Database.Validate` rejects it. Metastore engines are SQLite and PostgreSQL only. |
| JSON-RPC | REST `/storage/v1`. |

None of the dropped service methods are part of the `wdk.Services` interface, so
removing them costs nothing on the compatibility promise. (A handful of vestigial
DTO types — script-hash-history/utxo-status/exchange-rate structs — remain in
`pkg/wdk`/`pkg/defs` but are not on any interface.)

## Config-file migration

1. **ChainTracks:** rename `remote_url` → `url`; delete `mode`, `storage_path`,
   `bootstrap_url`, `bootstrap_mode`, `p2p_network`, `p2p_storage_path`.
2. **Services/broadcasters:** delete any WhatsOnChain/Bitails/GorillaPool/ARC
   endpoints and multi-provider fallback config; configure a single Arcade
   instance (`defs.Arcade{url, events_url, callback_token, callback_url,
   circuit_breaker{failure_threshold, health_probe_interval_seconds}}`). The
   `instances[]` field is reserved for a future HA mode and rejects more than one
   entry today.
3. **Database engine:** if you were on MySQL, move to PostgreSQL or SQLite — MySQL
   is validate-rejected.
4. **Exchange rate:** if you relied on a fetched rate, replace it with a static
   value in config.
5. **Throughput (new, optional):** to use the high-TPS fuel pool, add
   `defs.UTXOManagement{Strategy: throughput, ...}` — see
   [the high-throughput guide](high-throughput-guide.md).

## The one thing that changes your operational model

`go-arcade-toolbox` has **no UTXO discovery and no restore-from-seed** — a wallet
learns of its coins only from transactions it created and from
`InternalizeAction`. If your go-wallet-toolbox deployment leaned on rescanning or
an indexer to recover balances, that capability is gone by design. **Backing up
the wallet database becomes a correctness requirement.** See
[operations](operations.md).

> Note: the design blueprint (`go-wallet-toolbox/docs/arcade-only-design.md`)
> lists the storage-to-storage sync trio as a candidate to drop; in the as-built
> code the sync methods (`GetSyncChunk` / `FindOrInsertSyncStateAuth` /
> `ProcessSyncChunk`) are still present on `wdk.WalletStorageProvider`. Treat the
> blueprint as intent and the code as as-built.
